## 3. THE GATE — apply migrations 0016–0030

Two changes from the older command in earlier handovers. The range is now
`{16..30}`, and **`--single-transaction` is mandatory**.

```bash
set -a && source .env && set +a && \
for f in supabase/migrations/000000000000{16..30}_*.sql; do
  /usr/local/opt/postgresql@17/bin/psql "$DATABASE_URL" \
    --single-transaction -v ON_ERROR_STOP=1 -f "$f" || break
done
```

**Why `--single-transaction` matters.** psql autocommits every statement unless
told otherwise, and 0016–0028 carry no `begin`/`commit` of their own. A
migration that drops a policy and then fails before recreating it leaves that
table with RLS enabled and **zero policies** — deny-all, which presents to a
school as "our data has disappeared." This is not hypothetical: it happened on
the shadow cluster to `student_guardians` while 0029 was being written. 0029 and
0030 wrap themselves in an explicit transaction; the earlier ones do not.

**Rehearse first.** `./scripts/shadow-migrations.sh` applies the whole chain to
a throwaway local Postgres 17 cluster and reports the first failure. It is
green as of `c74e027` (71 tables, 60 policies, 204 functions).

### Post-apply checklist, in order

1. Confirm 0029's backfill notice. It prints
   `0029: retired N permission-less parent/student membership(s)`. **N is the
   number of parents who had full read of their entire school.** Expect > 0 on a
   database where any parent invite was ever accepted. Record the number.
2. Start the API with `AI_DRIVER=mock` and run the smokes that were blocked on

   `smoke-lifecycle` alone onboards two tenants.
3. Restart with the real provider and run `eval-ai.mjs`. Security categories
   must be 100%.
4. Spot-check that wave 1 did not over-restrict: sign in as a **bursar** and
   confirm `/finance` still renders invoices, and as a **teacher** and confirm
   it now shows nothing. That is the intended behaviour change and the one most
   likely to be reported as a regression.

## 4. What waves 0–3 actually changed

### Wave 1 — migration 0029, permission-aware RLS

Root cause: `app.is_tenant_member()` was the only predicate behind all 46
member-read policies, and it asked exactly one question — *is there an active
membership row?* It never asked what the user may see, nor whether the school is
still entitled to serve data. `@RequirePermission` was therefore **advisory
only**: anything reachable through PostgREST with the public anon key ignored it.

- **SEC-029-A** — finance tables and guardian PII now sit behind
  `app.has_permission(tenant, key)`, mirroring `TenantGuard` (school_owner and
  director bypass). A `teacher` is seeded with no `finance.*` and no
  `guardians.view`, yet could read every invoice, payment, journal entry, ledger
  line, guardian phone and email straight from the browser.
- **SEC-029-B** — **the find of the session, and the audit fleet missed it.**
  The applied `accept_invitation` (0004:215) mints an active membership for
  *every* invite including parents, and the `parent` role falls through
  `seed.sql`'s `else array[]::text[]` to zero permissions. Membership alone
  granted reads, so **every parent could read the entire school**: roster, DOBs,
  all guardian contacts, the full fee ledger, attendance, marks, SMS outbox.
  0026 stops minting new ones but never removed those already created — so
  applying 0016–0028 alone would have left this open permanently. 0029 backfills
  them to `revoked`.
- **SEC-029-C** — `is_tenant_member` now joins `tenants` and rejects
  `suspended`/`archived`. Suspension previously revoked nothing for direct
  browser/mobile reads; the billing lever did not actually pull.
  `is_tenant_member_any_status` keeps the tenant row itself readable so a
  locked-out school can be told why.
- **BUG-01** — a `platform_role` immutability trigger as defence in depth behind
  0026's column grant.

Measured on the shadow cluster, before (0028) vs after (0029):

| | teacher | bursar | parent |
|---|---|---|---|
| 0001–0028 | invoices 1, guardians 1, students 1 | — | invoices 1, guardians 1, students 1 |
| + 0029 | invoices **0**, guardians **0**, students 1 | invoices 1 ✓ | invoices **0**, students **0**, own guardian row only |

### Wave 2 — data destruction

- **xlsx zip bomb.** `XLSX.read` materialises the entire workbook before
  `MAX_ROWS` can apply, so a small highly-compressible file stalled the
  single-threaded event loop for every tenant. `imports.parser.ts` now prices
  expansion from the zip central directory before inflating. Measured on a
  purpose-built 1.92 MB bomb: **3.34 s / 359 MB → rejected in 0.00 s / 69 MB.**
  Regression-checked at 300, 4900 and 6000 rows and on CSV.
- **`DUP_EXISTING` is now a hard stop.** `import_staging_rows.decision` has no
  writer anywhere in the codebase, so `'skip'` was unreachable and
  `import_commit_chunk` committed flagged duplicates: re-uploading a corrected
  roster created a **second copy of every student**, with fresh admission
  numbers and fresh invoices.
- **`readAllPages()`** replaces three `.limit(10000)`/`.limit(20000)` reads.
  PostgREST caps responses at 1000 rows regardless of `.limit()`, silently — so
  the duplicate set, the student-number map and the already-imported set were
  arbitrary 1000-row slices. That double-created students and double-billed
  opening balances. Same fix applied to the library loan count.
- **Body limit.** `main.ts` had none, so body-parser's 100 kB default 413'd
  before any controller or zod schema ran; `/students/import` broke at ~380 rows
  while advertising 2000. Now 6 MB.

### Wave 3 — migration 0030, lifecycle

The schema modelled a full lifecycle but only one writer was ever built:
`app.onboard_school`.

- `students.status` had **no writer at all**, so a leaver held a paid plan seat
  forever (`tenant_entitlements` counts `status='active'`), kept being invoiced
  and kept receiving absence SMS. `app.set_student_status` also closes the open
  enrolment — leaving both rows active is what kept leavers on the register.
- `class_enrolments` was insert-only and `unique (student_id, academic_year_id)`
  blocked a second row, so one mistyped stream letter was permanent for the
  year and the pupil never appeared on their real register.
  `app.set_class_enrolment` handles assign and transfer as one upsert.
- No second academic year existed at all. `app.create_academic_year` builds year
  + terms and can clone the section grid; `app.activate_academic_year` closes
  the previous one.

New API: `PATCH /students/:id/status`, `PATCH /students/:id/enrolment`,
`POST /academics/years`, `/years/:id/activate`, `/grade-levels`, `/sections`.
Reuses `students.update`, `students.archive`, `academics.manage` — all three
were already seeded and granted but had no endpoint behind them.

Plus `smoke-lifecycle.mjs` (25th suite), three AI propose→confirm actions, and
the web UI.

## 5. What is NOT done — waves 4 and 5

Full detail per finding in `ATLAS_CODE_REVIEW_2026-07.md`. Priority order:

### Wave 4 — money and time

- **UTC vs EAT, systemic.** 63 `toISOString()` sites; exactly one
  (`clinic-view.tsx:45`) corrects for UTC+3. `payments.paid_on`,
  `invoices.issued_on` and `journal_entries.entry_date` also default to Postgres
  `current_date`, which is UTC on Supabase. Between 00:00–03:00 EAT every
  date-stamped financial fact lands on the previous day; between 21:00–00:00 the
  app's "today" is yesterday. Fix needs a shared `today()` helper on
  `Africa/Dar_es_Salaam` **and** a migration for the column defaults.
- **Payments have no idempotency key.** On Tanzanian mobile data a retried
  submit records a second payment, receipt and journal entry. A disabled button
  is the only defence.
- **`record_payment` accepts any `paid_on`** — far past or future — while
  stamping the journal entry `current_date`, so a receipt can vanish from the
  collection report while still clearing the invoice.
- **Payroll statutory-rates dialog crashes on open** — coded camelCase against a
  snake_case API response, so rates can never be edited or even inspected.
  Rates are labelled "%" but stored as fractions, with no upper bound.
- **A-Level division is never computed** (`report_card` handles `o_level` only)
  and points wrongly include General Studies.
- **`smoke-payroll.mjs` asserts the old over-taxing PAYE numbers** — the release
  gate currently encodes an illegal calculation.

### Wave 5 — hardening

- `smsMonthly` plan cap is resolved and displayed but **enforced nowhere**.
- `resolveDriver()` silently falls back to the console driver when Beem keys are
  blank, *and* `drain-outbox` marks rows `sent` before delivery — **you can ship
  believing SMS works when nothing has ever sent.**
- Outbox retries exhaust in ~30 min then fail permanently; no requeue path
  exists anywhere. No timeout on the Beem fetch.
- Eight module pages show a loading skeleton forever on a dropped connection.
- Mobile sessions sit in plaintext `AsyncStorage` while `expo-secure-store` is
  installed and unused. EAS builds ship with no env, pointing at `localhost:4000`.
- "Extend trial" downgrades a paying customer to `trialing` and later locks them out.
- **One test file in 51.5k LOC**, no CI, no Dockerfile, no deploy manifest.

## 7. Hard-won things worth not rediscovering

- **`create index if not exists` matches on NAME, not columns.** 0030 originally
  added an index byte-identical to one from 0004 and it was not suppressed —
  that would have doubled write cost on the hottest table for no read benefit.
- **A `SECURITY DEFINER` trigger sees `current_user` as the function owner**, not
  the caller. 0029's `platform_role` guard was written that way at first, so its
  role check could never fire and the escalation it existed to stop succeeded.
  It is deliberately `SECURITY INVOKER`.
- **Testing RLS as `postgres` proves nothing** — superusers bypass RLS entirely.
  Use `begin; set local request.jwt.claim.sub='<uuid>'; set local role
  authenticated; …`. `SET LOCAL` outside a transaction is a silent no-op, which
  makes a broken test look like a passing one.
- **Business errors must be `{ code: 'STABLE_CODE' }`, never a bare string.**
  Both error maps key off `code`; a message-only `ForbiddenException` renders as
  raw English to a Swahili user.
- **Adding an AI action is not enough** — `SYSTEM_PROMPT` rule 9 in
  `ai.controller.ts` enumerates what the model may never do, and a stale entry
  there makes it refuse a capability it now has.
- The unix socket path limit (103 bytes) means a scratch Postgres cannot put its
  socket in the session scratchpad; `pg_ctl` on this Mac also needs
  `LC_ALL=en_US.UTF-8`. Both are handled in `scripts/shadow-migrations.sh`.
