no-go for the reasons in `GO_LIVE_READINESS_2026-08-03.md` §blockers.

## 5. What changed, by area

### English-only (`903c9f3`)

- `packages/i18n` went 1687 → ~840 lines. `getDict()` now takes no argument;
  `Lang` and `LANG_COOKIE` no longer exist.
- 71 web files lost the `lang` prop. `language-switcher.tsx` deleted. Settings'
  interface/messaging-language cards and the onboarding language picker are
  gone; schools are created `defaultLanguage: "en"`.
- **Mobile defaulted to Swahili** (`useState<Lang>("sw")`) — that provider is
  removed; `useT()` is unchanged for every screen.
- **The SMS bodies guardians receive were hardcoded Swahili** in
  `drain-outbox.ts`. attendance.absent, clinic.visit and fees.reminder are now
  English.
- AI `SYSTEM_PROMPT` rule 6 told the model to answer in Kiswahili; now
  English-only.

**Deliberately kept** — data and input tolerance, not UI language: Kiswahili as
a taught subject in `subjects.presets.ts` and the HKL combination; the Swahili
spreadsheet header aliases in `imports/import-domains.ts` (schools' real Excel
files use them); the `name_sw` columns.

### Marketing surface

- **Host split** (`lib/hosts.ts`, `proxy.ts`): apex serves marketing, `app.`
  serves the product. `NEXT_PUBLIC_ROOT_DOMAIN` is set in **production only** —
  empty locally so everything stays testable on one host. **The dashboard moved
  off `/` to `/dashboard`.**
- Verified with `Host:` headers against a split-mode server: apex `/` 200; app
  bare root → `/login`; apex `/dashboard` → app host with query preserved; app
  `/blog` → apex; `/api/…` never redirects; robots.txt differs per host and
  never redirects; `/blog/%2e%2e/dashboard` judged as an app path; `//evil.tz`
  cannot escape the origin; localhost redirects nowhere.
- **Design system is scoped.** Everything lives under `.atlas-marketing` in
  `(marketing)/marketing.css`. **Do not hoist it into `globals.css`** — the
  product keeps `design.md` (Atlas Blue #0052ff, weight-400 headlines).
- `lib/offer.ts` is the only place the price lives; the visible page and the
  JSON-LD Offer both render from it.

### Product fixes found along the way

- **Collections chart Y-axis** had `width={64}` and no formatter, so a
  nine-digit TZS figure was clipped and rendered as `0000000`. It read as a
  broken chart and would have shipped as the marketing hero image.
- **Avatar menu crashed on open.** `DropdownMenuLabel` (Base UI `GroupLabel`)
  was nested in a `DropdownMenuItem`, throwing "MenuGroupContext is missing".
  Presented as a 404. Profile now goes to `/settings`; **Support was removed**
  — it had no destination and none exists yet.
- **Dark mode** existed in `globals.css` under `.dark` and was never switched
  on. Toggle is in the sidebar footer; the class is applied by an inline script
  **before first paint** so dark users get no light flash.
- **`seed-demo.mjs` froze itself** on a hardcoded `new Date('2026-07-05')`, so
  every later run produced attendance outside the dashboard's 30-day window and
  a fully-seeded school showed "No data yet". Now anchored on today.

## 6. Open threads

1. **`LEAD_EMAIL_DRIVER` is unconfigured, so the funnel's fallback is unproven.**
   Storage works. But if the database is unreachable, the lead is only written
   to the server log at error level and the visitor sees an error. Set
   `LEAD_EMAIL_DRIVER=resend`, `RESEND_API_KEY`, `LEAD_EMAIL_TO`, then rehearse
   the degraded path with the database switched off — the brief asks for this
   specifically.
2. **`src/data/schools.json` ships empty.** Dev-only sample rows are hard-gated
   out of production. The real TAMISEMI/NECTA register must be loaded before any
   SMS campaign, and it must exclude phone numbers and emails.
3. **`/terms` and `/privacy` are drafts on `main`.** Both carry a loud
   "Draft — not yet in force" banner and bracketed placeholders (registered
   entity, address, PDPC reference, DPO contact, retention schedule, support
   hours, SMS bundle price). **The banner must stay until Tanzanian counsel
   signs off.** The privacy notice states plainly that the cross-border
   transfer permit is not obtained and the assistant must stay on pilot data —
   keep it that way; see `TANZANIA_PRIVACY_CHECKLIST.md`.
4. **Screenshots are partly placeholders.** Dashboard, debtors and the student
   register are real. Attendance, the assistant, invoices, report cards and the
   parent portal still render labelled placeholders naming the exact screen
   each needs. Layout is final; only pixels are missing.
5. **0036 corrected a real mistake in 0035** and the pattern is worth
   remembering: the public `tenant_sms_usage` wrapper admitted tenant
   **members** only, so the API — which holds the service-role key and is a
   member of nothing — got `SMS_USAGE_FORBIDDEN` on the very counter the
   function exists to feed. The drainer was never affected because it calls the
   app-schema function directly. **Any new `public.*` wrapper must decide
   explicitly whether the service role is allowed through.**

## 7. Hard-won things worth not rediscovering

- **`WEB_ORIGIN` must match the web port or every client-side API call dies
  silently.** It defaults to `http://localhost:3000`. On 3001/3002 the CORS
  preflight answers 204 *without* a matching `Access-Control-Allow-Origin`, so
  the browser never sends the real request — **the API logs nothing** and the
  page sits on "Loading…". Server components keep working, so it looks like
  only some pages are broken. This cost real time; it is now in CLAUDE.md.
- **JSX strips leading whitespace from any text chunk containing a newline.**
  `</strong> word` wrapping to the next line renders as `wordword`. Use
  `{" "}`. Two of these shipped into the privacy notice before being caught by
  sweeping the rendered HTML of every marketing page.
- **Deleting a Supabase auth user needs the `profiles` row deleted first**,
  otherwise `deleteUser` returns an opaque 500.
- **Agents are blocked from `supabase db push` by the permission classifier.**
  It is not an auth failure and a new token will not help. The fix is a Bash
  permission rule; this repo now has one in `.claude/settings.local.json`
  (gitignored, so it is per-machine) scoped to `db push` / `migration list` /
  `migration repair`, **with an explicit deny on `supabase db reset`**.
- **Native `<select>` elements cannot be driven by browser automation** on this
  setup, which is why the attendance and assistant screenshots are outstanding.
- The demo tenant's data is synthetic — `seed-demo.mjs` generates the names and
  guardian phones are sequential (`+255744000101`, `…102`). That is why
  publishing its screenshots on a public marketing site is safe. **Verify this
  again if the demo tenant is ever re-seeded from real data.**
